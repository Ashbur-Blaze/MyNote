# CLR / JIT / IL / 栈 / 堆 学习笔记

.NET 程序的执行原理，从源代码到机器码的完整链路。

---

## 一、总览

### 执行链路

    C# 源代码 (Program.cs)
        ↓ Roslyn 编译器
    IL 中间语言 + 元数据
        ↓ 打包
    程序集 (.dll / .exe)
        ↓ CLR 加载
    CLR 运行时
        ↓ JIT 编译
    本机机器码
        ↓
    CPU 执行

### 一句话理解

| 概念 | 一句话 |
| --- | --- |
| IL | C# 编译后的“中间语言”，跨平台通用 |
| CLR | .NET 的运行时管家，负责加载、编译、GC、异常、线程 |
| JIT | 运行时把 IL 翻成机器码 |
| 栈 | 快速、小巧、自动管理，存局部变量 |
| 堆 | 大、慢、由 GC 管理，存引用类型对象 |

## 二、IL 中间语言

### 定义

IL（Intermediate Language）是 .NET 编译器输出的中间表示，与 CPU 架构无关，是一种基于栈的指令集。

### 特点

| 特点 | 说明 |
| --- | --- |
| 平台无关 | 可在任何支持 CLR 的平台运行 |
| 基于栈 | 操作通过压栈/弹栈完成 |
| 强类型 | 每条指令有明确类型 |
| 可验证 | CLR 验证器可检查类型安全 |

### 示例

C# 代码：

    int Add(int a, int b)
    {
        return a + b;
    }

对应 IL：

    ldarg.0      // 加载参数 a 到栈
    ldarg.1      // 加载参数 b 到栈
    add          // 弹出两个值，相加，结果压栈
    ret          // 返回栈顶值

### 常用 IL 指令

| 指令 | 含义 |
| --- | --- |
| ldarg.N | 加载第 N 个参数 |
| ldloc.N | 加载第 N 个局部变量 |
| stloc.N | 存入第 N 个局部变量 |
| add / sub / mul | 算术运算 |
| call | 调用方法 |
| callvirt | 虚方法调用 |
| newobj | 创建对象 |
| box / unbox | 装箱 / 拆箱 |
| ret | 返回 |

### 衍生：元数据

IL 和元数据一起打包在程序集中。元数据描述：

- 类型定义（类、接口、结构体）
- 成员定义（字段、方法、属性）
- 引用（引用了哪些程序集）
- 特性（Attribute）

元数据是反射（Reflection）的基础。

### 衍生：Roslyn 编译器

C# 官方编译器平台，编译管线：

    语法分析 → 语义分析 → IL 生成

- 开源：github.com/dotnet/roslyn
- 提供 API，可做代码分析、重构工具

## 三、CLR 公共语言运行时

### 定义

CLR（Common Language Runtime）是 .NET 的执行引擎，负责加载、编译、执行、管理托管代码。

### 六大职责

| 职责 | 说明 |
| --- | --- |
| 程序集加载 | 定位、加载、验证 .dll / .exe |
| JIT 编译 | IL → 机器码 |
| 内存管理 | GC 自动回收堆对象 |
| 类型安全 | 验证 IL，防止非法访问 |
| 异常处理 | 管理 try-catch 执行 |
| 线程管理 | 调度托管线程 |

### 架构层次

    .NET 应用程序
        ↓
    基础类库（BCL）—— File、Console、SHA256
        ↓
    CLR 执行引擎
    ├── 程序集加载器
    ├── JIT 编译器
    ├── 垃圾回收器（GC）
    ├── 类型验证器
    ├── 异常处理引擎
    └── 线程调度器
        ↓
    操作系统
        ↓
    硬件

### 衍生：托管 vs 非托管代码

| | 托管代码 | 非托管代码 |
| --- | --- | --- |
| 运行环境 | CLR | 直接由 OS 执行 |
| 内存管理 | GC | 手动 malloc / free |
| 类型安全 | 验证器保证 | 无保证 |
| 例子 | C#、F# | C、C++、Rust |

### 衍生：程序集（Assembly）

.NET 的部署和版本控制单元，包含：

- IL 代码
- 元数据
- 清单（名称、版本、依赖）
- 资源（可选）

| 类型 | 扩展名 |
| --- | --- |
| 可执行程序集 | .exe |
| 库程序集 | .dll |

## 四、JIT 即时编译

### 定义

JIT（Just-In-Time Compilation）是 CLR 在运行时把 IL 编译为目标平台机器码的编译器。

### 编译流程

    IL
        ↓ 导入
    内部中间表示（IR）
        ↓ 优化
    优化后的 IR
        ↓ 寄存器分配
        ↓ 代码生成
    机器码

### 关键机制

| 机制 | 说明 |
| --- | --- |
| 方法级编译 | 以方法为单元，首次调用时编译 |
| 延迟编译 | 用到了才编译 |
| 编译缓存 | 编译过的机器码缓存 |
| 分层编译 | Tier 0（快编译）→ Tier 1（优化编译） |
| 内联 | 小方法嵌入调用点 |
| 去虚拟化 | 虚调用转直接调用 |
| SIMD | 向量化指令生成 |

### 分层编译

    第 1 次调用
        ↓
    Tier 0：快速编译，不优化，立即执行
        ↓
    方法被多次调用（热点）
        ↓
    Tier 1：重新编译，深度优化
        ↓
    后续调用使用优化后的机器码

目的：启动快 + 运行快。

### 衍生：AOT 提前编译

| | JIT | AOT |
| --- | --- | --- |
| 编译时机 | 运行时 | 发布时 |
| 启动速度 | 较慢 | 快 |
| 跨平台 | IL 跨平台 | 每平台单独编译 |
| 反射支持 | 完整 | 受限 |

Native AOT：.NET 7+ 支持，直接编译成本机可执行文件。

ReadyToRun (R2R)：发布时预编译 IL 为机器码，减少 JIT 开销。

## 五、栈 Stack

### 定义

栈是线程私有的内存区域，后进先出（LIFO），用于存储方法调用上下文和局部变量。

### 特点

| 特点 | 说明 |
| --- | --- |
| 线程私有 | 每个线程一个栈 |
| 大小固定 | 通常 1 MB |
| 分配速度快 | 移动栈指针即可 |
| 自动管理 | 方法退出时自动释放 |
| 后进先出 | 最后压入的最先弹出 |

### 栈帧

每次方法调用，在栈上分配一个栈帧，包含：

- 方法参数
- 局部变量
- 返回地址
- 保存的寄存器状态

    高地址
    ┌─────────────────┐
    │  Main 的栈帧     │
    ├─────────────────┤
    │  Add 的栈帧      │  ← 当前栈顶
    │  ├── 参数 x, y  │
    │  ├── 局部 sum   │
    │  └── 返回地址   │
    └─────────────────┘
    低地址

### 栈溢出

- 递归无终止条件 → 栈帧无限累积 → StackOverflowException
- 无法被 catch，进程直接终止

### 衍生：调用约定

方法调用时参数如何传递、栈由谁清理：

| 约定 | 说明 |
| --- | --- |
| cdecl | 调用方清理栈 |
| stdcall | 被调用方清理栈 |
| fastcall | 部分参数用寄存器 |
| CLR 约定 | 由 CLR 统一管理 |

## 六、堆 Heap

### 定义

堆是进程共享的内存区域，用于存储引用类型对象，由 GC 自动管理。

### 特点

| 特点 | 说明 |
| --- | --- |
| 进程共享 | 所有线程共享 |
| 大小大 | 受物理内存限制 |
| 分配速度慢 | 需查找空闲块 |
| 自动管理 | GC 回收 |
| 碎片化 | 可能产生内存碎片 |

### 托管堆结构

    托管堆
    ├── Gen 0（新分配的小对象）
    ├── Gen 1（从 Gen 0 存活下来的）
    ├── Gen 2（长命对象）
    └── LOH（大对象堆，> 85KB）

### 对象布局

    ┌──────────────────┐
    │  对象头（Header） │  ← 同步块索引、方法表指针
    ├──────────────────┤
    │  字段数据         │
    └──────────────────┘

### 衍生：GC 垃圾回收

分代、标记-清除、压缩式回收器。

| 阶段 | 说明 |
| --- | --- |
| 标记 | 从根出发，标记可达对象 |
| 清除 | 回收未标记对象 |
| 压缩 | 移动存活对象，消除碎片 |

分代假设：

- 大部分对象很快死亡（Gen 0）
- 存活越久越可能继续存活（Gen 2）

### 衍生：大对象堆（LOH）

- 大于 85,000 字节的对象分配在 LOH
- LOH 不压缩
- 碎片化是长期运行应用的常见问题

### 衍生：写屏障

维护跨代引用（Gen 2 → Gen 0），保证 GC 正确性。

### 衍生：终结器

    ~MyClass()   // 终结器
    {
        // 释放非托管资源
    }

- 由 GC 在回收前调用
- 时机不确定
- 推荐用 IDisposable + using 替代

### 衍生：IDisposable 与 using

    using FileStream stream = File.OpenRead(path);
    // 离开作用域自动调用 Dispose()

用于释放非托管资源（文件句柄、网络连接）。

### 衍生：装箱与拆箱

装箱：值类型 → 引用类型

    int x = 42;
    object obj = x;   // 堆上分配

拆箱：引用类型 → 值类型

    int y = (int)obj;   // 从堆复制到栈

代价：堆分配 + 内存复制。用泛型避免装箱。

## 七、栈 vs 堆

| 维度 | 栈 | 堆 |
| --- | --- | --- |
| 归属 | 线程私有 | 进程共享 |
| 大小 | 1 MB（默认） | 受物理内存限制 |
| 分配速度 | 极快 | 较慢 |
| 释放方式 | 自动（函数退出） | GC 回收 |
| 顺序 | LIFO | 无 |
| 碎片 | 无 | 可能碎片化 |
| 存储 | 值类型局部变量、参数 | 引用类型对象、装箱值 |
| 溢出 | StackOverflowException | OutOfMemoryException |

### 变量分布

    int count = 0;                              // count 在栈上
    string path = args[0];                      // path 引用在栈，字符串在堆
    Dictionary<string, string> dict = new ...;  // dict 引用在栈，字典在堆

图示：

    栈                          堆
    ┌──────────┐
    │ count: 0 │
    ├──────────┤
    │ path: ●──┼──────────→ "C:\test"
    ├──────────┤
    │ dict: ●──┼──────────→ { Dictionary }
    └──────────┘

## 九、Rust 对照

| 概念 | C# | Rust |
| --- | --- | --- |
| 编译目标 | IL → JIT → 机器码 | 直接机器码 |
| 运行时 | CLR | 无（或极小） |
| 内存管理 | GC | 所有权 + 借用 |
| 栈 | 有 | 有 |
| 堆 | GC 管理 | 所有权管理 |
| 装箱 | 值→引用 | Box<T> |
| 接口 | interface | trait |
| 空值 | null | Option<T> |
| 错误 | 异常 | Result<T, E> |
| 启动速度 | 较慢 | 极快 |
| 运行时开销 | 有 | 无 |
